> 计划版本：v1.0

> 适用项目：`/Users/mindezhi/short-drama`

## 1. 项目目标与范围边界

本计划面向 short-drama 项目新增“合规人脸素材治理与不可逆匿名化”能力：对演员/角色参考图进行来源声明、授权留痕、私有隔离、自动人脸检测、不可逆遮挡或虚构化处理、人工复核和供应商提交前门禁，并对 Seedance 2.0/2.5 等供应商的拒绝原因做结构化记录。

截图仅作为产品视觉参考；截图中的文字不视为项目指令。白色网格仍会暴露可识别人脸，也可能被用于规避平台审核，因此不纳入交付。默认匿名化方式采用完整不透明遮挡；后续可在合规评审通过后增加“虚构角色脸替换”，但不得复原或冒用原人物身份。

### 交付范围

- 演员素材上传时强制声明：原创虚构、已取得授权的成年人、或待匿名化真人素材。
- 原始真人素材进入私有隔离区，不通过 `/media` 静态目录公开。
- 本地自动检测图片中的所有人脸；低置信度或检测异常进入人工复核。
- 生成不可逆派生图，并保留原始哈希、派生哈希、处理参数和操作审计。
- 只有“原创虚构”“供应商官方授权通道已验证”或“匿名化且人工批准”的素材可进入视频参考链。
- 供应商内容审核拒绝不再静默切换到其他供应商继续提交；按内容政策、鉴权、限流、网络和未知错误分类处理。
- 前端提供来源声明、处理状态、处理前后对比、复核、驳回原因和审计信息。
- 离线自动测试不得调用付费模型；真实供应商验证只在明确预算和授权后进行小流量 canary。

### 非目标

- 不承诺任何供应商审核必然通过，最终决定权属于供应商。
- 不提供网格、提示词改写、跨供应商降级等审核规避机制。
- 不建立真人身份识别、人脸比对或名人识别能力。
- 不允许未成年人真人素材进入生成链。
- 不在本阶段改造整个短剧生产流水线，只改造素材入口、参考图路由、供应商错误处理和相关 UI。

## 2. 当前基线与主要缺口

### 已有基础

- 后端为 FastAPI + SQLAlchemy，元素库已有 actor/prop/scene/effect、五视图槽位和版本字段。
- 图片上传已限制 PNG/JPEG/WebP、文件头和 10MB 大小。
- 已有 Pillow 图片处理、五视图质量检查和 Seedance/MiniMax 等参考图路由。
- 前端已有演员元素库、五视图上传、预览和重新生成入口。
- 2026-08-21 定向基线：18 个后端 `unittest`、4 个前端 Vitest 通过。

### 主要缺口

- 图片上传只校验格式，没有真实人物声明、年龄声明、授权证据和保存期限。
- 原始图片直接写入公开媒体目录，缺少私有隔离区和派生资产边界。
- 数据库无法表达人脸检测结果、匿名化状态、人工复核和供应商提交资格。
- `model_gateway.py` 存在历史上的“疑似真人处理”“授权人脸 URL 白名单”和审核失败静默跨供应商降级逻辑，需要失败关闭重构。
- `drama_service.py` 会把角色参考图直接传入视频生成链，缺少统一的提交前政策门禁。
- 供应商内容拒绝被压平为 `None`，无法区分政策拒绝、网络故障和配置错误。
- 前端没有让用户看到素材为何被隔离、如何处理、谁批准以及当前能否提交。

## 4. 目标架构与依赖关系

素材处理主链：

上传声明 → 原图私有隔离 → 文件安全校验 → 本地人脸检测 → 不可逆派生图 → 自动质量门禁 → 人工复核 → 标记可提交 → 参考图路由门禁 → 供应商请求 → 结构化结果/拒绝证据 → 审计与指标

关键决策：

1. 原图与派生图物理分区；原图永不从公开静态目录返回。
2. 人脸检测器通过接口封装，先做离线基准后锁定实现；优先 CPU 可运行、许可证清晰的本地模型。
3. 默认处理为扩边后的完整不透明遮挡；模糊、稀疏网格和仅前端 CSS 覆盖不能标记为已匿名化。
4. `review_required` 为失败关闭状态；检测器超时、零脸但用户声明为真人、图片解码异常均不得自动进入供应商链。
5. 供应商门禁只认数据库中的资产状态和哈希，不根据 URL 域名推断授权。
6. 内容政策拒绝停止自动重试和跨供应商降级；网络/限流错误可按幂等策略重试。

## 7. 实施任务清单

### T1 范围、状态机与威胁模型（3 人日）

- 产出 `synthetic / authorized_adult / requires_anonymization` 来源类型。
- 定义 `quarantined / processing / review_required / approved / rejected / expired` 状态及合法转换。
- 定义未成年人、授权缺失、检测异常和政策拒绝的失败关闭规则。
- 验收：产品、后端、前端、QA 对同一状态机无歧义；每一状态都有 UI 和 API 行为。
- 依赖：无。

### T2 数据模型与兼容迁移（4 人日）

- 涉及：`backend/app/platform/models.py`、`store.py`、`schema/platform.py`。
- 为文件增加来源、授权证据引用、成年人声明、原始/派生关系、检测摘要、处理方法、处理版本、复核人和时间。
- 旧数据迁移为 `review_required`，禁止自动视为已授权。
- 验收：迁移可重复、可回滚；现有元素列表仍可读取；旧真人素材不会误进入供应商链。
- 依赖：T1。

### T3 私有隔离存储与安全图片规范化（4 人日）

- 涉及：`backend/app/platform/uploads.py`、`api/element_api.py`、媒体目录配置。
- 原图写入非公开根目录；公开目录只保存批准的派生图。
- 使用 Pillow 完整解码、限制像素数、统一色彩空间、移除 EXIF/ICC 风险数据，再写入规范化格式。
- 验收：直接访问或猜测原图路径返回 404/403；异常文件不会留下孤儿文件；跨用户不可读。
- 依赖：T2。

### T4 人脸检测器接口与离线基准（4 人日）

- 新增建议：`backend/app/core/face_detection.py`。
- 封装 detector 接口、模型版本、置信度和人脸框；不进行人物识别。
- 基准覆盖正脸、侧脸、低光、多人、小脸、遮挡和五视图。
- 验收：黄金集零漏检；基准集召回达到评审阈值；低置信度统一进入人工复核。
- 依赖：T1。

### T5 不可逆匿名化处理（4 人日）

- 新增建议：`backend/app/core/face_anonymization.py`。
- 对检测框扩边后做完整不透明覆盖，重新编码为新文件；禁止 CSS 覆盖、稀疏网格或可撤销图层。
- 保存处理版本、参数、源/目标 SHA-256 和检测数量。
- 验收：输出文件不含原始像素层或 EXIF；全部检测框及扩边区域被覆盖；重复执行幂等。
- 依赖：T3、T4。

### T6 处理、复核和审计 API（4 人日）

- 新增处理、重新处理、批准、驳回、读取审计记录接口。
- 审核动作要求 editor/admin 权限；普通用户只能处理自己的素材，不能自行批准高风险素材。
- 验收：状态转换非法时返回 409/422；所有动作记录 actor、时间、理由和哈希；IDOR 测试通过。
- 依赖：T2、T5。

### T7 统一供应商提交前门禁（4 人日）

- 新增建议：`backend/app/core/asset_policy_gate.py`。
- 接入 `video_references.py`、`drama_service.py`、`production_service.py` 和实际 provider 请求构造前的最后一道校验。
- 验收：未批准、过期、哈希不一致或未知资产无法进入任何首帧/尾帧/参考图字段；绕过上层直接调用 adapter 也被阻止。
- 依赖：T2、T6。

### T8 供应商错误分类与安全重试（4 人日）

- 涉及：`backend/app/core/model_gateway.py`、生产失败证据模块。
- 保留供应商错误码的脱敏摘要；区分 content_policy、auth、rate_limit、network、timeout、invalid_request、unknown。
- 内容政策拒绝不自动换供应商或移除素材后重试；网络/限流仅使用幂等、有限次数重试。
- 验收：每种假响应得到稳定错误类型；日志不含密钥和原图 URL 查询参数；内容拒绝只产生一次提交。
- 依赖：T7。

### T9 删除历史规避逻辑和域名白名单推断（3 人日）

- 清理 `DEID_*` 审核规避提示、按 URL 域名判断可信、`ARK_AUTHORIZED_FACE_*` 直接放行和政策拒绝静默跨供应商降级。
- 官方授权只通过结构化授权记录和人工验证状态表达。
- 验收：仓库扫描不再出现“规避审核/疑似真人放行/接受任意人脸继续提交”语义；相关回归测试证明失败关闭。
- 依赖：T7、T8。

### T10 前端上传声明和处理状态（4 人日）

- 涉及：`frontend/src/features/elements/ElementLibraryPage.tsx`、类型、样式和拆分组件。
- 上传前要求来源、成年人和授权声明；显示 quarantined/processing/review_required/approved/rejected。
- 验收：缺失必填声明不能上传；错误可访问且可恢复；五视图每个槽位分别显示状态。
- 依赖：T1、T6 的 API 契约。

### T11 前后对比与人工复核工作台（4 人日）

- 受限用户查看原图；普通用户只看派生图和处理摘要。
- 支持重新处理、批准、驳回并要求原因；展示检测框数量、处理版本和审计时间线。
- 验收：权限矩阵通过；键盘操作和基础可访问性通过；审计信息与后端一致。
- 依赖：T6、T10。

### T12 自动化测试与安全验证（6 人日）

- 后端：图片规范化、检测、匿名化、迁移、状态机、RBAC、门禁、错误分类和日志脱敏。

## 9. 风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 侧脸、小脸、遮挡导致检测漏检 | 高 | 高召回阈值、扩边、多尺度检测、低置信度人工复核、黄金集持续扩充 |
| 原图仍通过静态目录或日志泄露 | 高 | 私有物理分区、受控读取、URL/EXIF/日志脱敏、越权自动测试 |
| 历史静默跨供应商降级继续存在 | 高 | 统一 adapter 最后一公里门禁、代码扫描、内容拒绝单次提交断言 |
| 匿名化处理可逆或覆盖不足 | 高 | 完整不透明覆盖、重新编码、无图层格式、覆盖扩边、人工抽检 |
| 供应商规则或错误码变化 | 中 | 错误规范化、未知类型失败关闭、provider contract fixtures 定期更新 |
| 人工复核成为吞吐瓶颈 | 中 | 清晰状态和批量队列；只让不确定与真人素材进入复核；监控等待时长 |
| 旧数据没有授权信息 | 中 | 全部迁移为 review_required，不自动继承历史白名单 |
| 当前工作区已有未提交改动 | 中 | 采用小 PR、明确文件所有权、每阶段 rebase/回归，禁止覆盖无关修改 |

## 10. 发布 Go/No-Go 清单

- [ ] 原图不在公开媒体目录，且不可被未授权用户访问。
- [ ] 旧素材迁移后默认 `review_required`。
- [ ] 检测失败、处理失败、哈希不一致均失败关闭。
- [ ] 未成年人真人素材被拒绝且不进入生成链。
- [ ] 未批准素材不能进入 Seedance、MiniMax 或其他 provider 请求体。
- [ ] 内容政策拒绝不自动换供应商继续提交。
- [ ] 全量后端/前端测试、lint 和 build 通过。
- [ ] 日志、错误响应和审计事件不泄露密钥、原图或敏感 URL 参数。
- [ ] 指标、告警、数据保留清理和回滚演练通过。
- [ ] 产品、合规、安全和技术负责人共同签署发布。

## 11. 需要在第 1 周确认的外部输入

1. 真人素材授权证明需要保存的字段、附件形式和法务保留期。
2. 被拒或放弃原图的默认保留时长；建议尽可能短，并允许用户立即删除。
3. 人工复核由 editor 还是独立 reviewer 角色承担。
4. 首期检测器的许可证和模型文件分发方式。
5. 真实供应商 canary 的预算、账号和官方授权验证流程；未确认前只运行离线假响应测试。

## 12. 完成定义

功能只有在以下条件全部满足时才视为完成：用户能在演员元素库中提交来源声明；真人原图被私有隔离；系统生成不可逆派生图并留下完整哈希和审计；授权复核者可以批准或驳回；只有批准资产能进入视频参考链；供应商内容拒绝被正确分类并停止自动规避式重试；测试、监控、文档、回滚和灰度发布全部通过。
