# 五段式分段判据

> 本文件是项目自撰的 clean-room 补充说明，只解决「一条信息该落进哪一段」和
> 「时间线该切几段」两个问题。段落名沿用用户指定的五段式：主体、风格、时间线、BGM、限制。
> 与 `sd25-pe` 冲突时一律以 `sd25-pe` 为准，本文件不重新定义任务路由与参数分离。

## 一、先判断这条信息约束的是什么

不要按信息的表面词性归类，按它**约束了成片的哪一层**归类。判断顺序自上而下，命中即停：

| 提问 | 命中即落入 | 说明 |
|---|---|---|
| 它约束的是「画面里存在什么」吗？ | 主体 | 人、物、场景、数量、归属、以及每份素材负责哪一项 |
| 它约束的是「同一件东西怎么被看见」吗？ | 风格 | 光线、色彩、质感、成片形式、剪辑与镜头基调 |
| 它约束的是「什么时候变成什么」吗？ | 时间线 | 状态迁移、动作、单个主运镜、结束状态 |
| 它约束的是「观众听到什么」吗？ | BGM | 音乐、对白、关键音效，以及它们与画面的对齐点 |
| 它约束的是「不允许出现什么」吗？ | 限制 | 本条任务真实存在的风险，不是通用负向词 |
| 以上都不是 | 不写 | 接口参数、分析过程、评测说明一律不进 Prompt |

常见的归类分歧，按下面这张表定案，不要凭直觉分配：

| 容易放错的信息 | 正确落段 | 放错的后果 |
|---|---|---|
| 「@图1 只锁人物脸和服装，不带背景」 | 主体 | 放进限制会被读成负向词，素材职责失效 |
| 「全片同一位人物」 | 主体 | 放进限制会让模型把「同一人」当成事后纠错而非前置事实 |
| 「快速硬切与手持交替」 | 风格 | 放进时间线会和该段的唯一主运镜打架 |
| 「第 3 秒推近到手部」 | 时间线 | 放进风格会丢掉发生时刻 |
| 「他说：{我知道了}」 | BGM | 台词是声音层；主体只写谁在场，不写说了什么 |
| 「画面不显示字幕」 | 限制 | 字幕是文字载体风险，不是风格 |
| 「输出 16:9 / 时长 15 秒 / 4K」 | 不写 | 接口参数，按 `sd25-pe` 参数分离规则由页面或接口设置 |

## 二、主体段的最小完备集

主体段写完后自查四项，缺一项就补，不缺不加：

1. **在场清单**：每个会出场的人物、群体、关键道具、场景各占一行，数量写死。
2. **恒定特征**：每个在场项写出全片不变的可见特征（外貌、服装、结构、材质、布局）。
3. **关系与归属**：谁持有哪件道具，谁在哪个空间的哪一侧，交接后归谁。
4. **素材职责**：一行只绑定一个主体与一份主素材，并写明该素材不承担什么。

没有参考素材时第 4 项整体省略，不写空占位。参考素材的一一映射、
`【未采用素材】` 与素材引用保真规则以 `sd25-pe` 为准，本段只负责把它们放在主体段内。

## 三、时间线分段判据

### 3.1 先决定用不用数字

- 用户已经写出事件时间段 → 保留数字，按连续、不重叠、覆盖到结尾组织。
- 只有接口参数给出总时长 → 使用不带数字的阶段，**不得**把参数反写成新的秒数区间。
- 用户明确说原时间段是硬约束、但与接口参数冲突 → 保留数字，把冲突交回用户，不自行改写。

### 3.2 分几段由状态变化数决定

分段数不是先定的常数，按下面三步推出来：

1. 数出这条创意里**必须被看见**的状态变化个数 N（每个变化都要有可观察的前后差异）。
2. 初始段数取 N；若某两个变化在同一空间、同一主体、同一运镜下自然连贯，合并成一段。
3. 再用两条边界修剪：
   - **下界**：每段至少要能容纳「进入 → 动作 → 离开」三拍，段落过短会让动作做不完。
   - **上界**：段落越多，跨段一致性风险越高；宁可合并次要变化，也不要为了凑段数拆分。

结果通常落在 4 到 8 段之间，但**这是推出来的结果，不是先验模板**。情绪戏段数更少、
把时间给到表演展开；动作戏段数更多，但每增加一段都要问一次「这段的状态变化是否真的不同」。

### 3.3 每一段的四格结构

每段严格写四格，顺序固定，缺格即视为该段未写完：

| 格位 | 内容 | 常见错误 |
|---|---|---|
| 进入状态 | 本段开始瞬间画面里已经成立的事实 | 直接从动作起笔，丢掉承接 |
| 唯一主动作 | 一个可以被摄影机拍到的动词 | 一段塞两个并列主动作 |
| 唯一主镜头动作 | 一个景别加一种运镜 | 同段同时要求固定机位与环绕 |
| 离开状态 | 本段结束瞬间的可观察结果 | 写成评价（「非常燃」）而非状态 |

**咬合规则**：上一段的离开状态必须能原样充当下一段的进入状态。写完时间线后从头到尾
读一遍离开状态串，若某处需要脑补一个没写出来的动作才能接上，说明中间漏了一段。

### 3.4 动词选择

只使用能被拍到的动词：抬手、转身、蹬地、拉开、倒入、扣合、落地、递出。
「精彩地」「酷炫地」「激烈地」不描述任何可见变化，一律替换成具体动作或删除。
抽象卖点按 `sd25-pe` 的「初始状态 → 具体操作 → 可观察结果」展开。

## 四、BGM 段的三条判据

1. 用户没有要求音乐时写「无 BGM」，但**不得**自动补写音乐类型、BPM 或乐器。
2. 有音乐时写清类型、速度、核心乐器、情绪走向、结尾收束方式；需要卡点时把对齐点
   绑到具体时刻，而不是笼统写「与画面同步」。
3. 对白逐条绑定说话人、原文、语言（用户指定时）、表达方式与画内外位置；
   未说话的人物写明自然闭口。音效写清来源，避免被当成背景音乐。

台词符号体系（音乐 `()`、音效 `<>`、台词 `{}`、字幕 `【】`）与语言指定规则以 `sd25-pe` 为准。

## 五、限制段的选择判据

限制段的作用是**收敛已经写清楚的内容**，不是补救没写清楚的内容。写限制前先做两件事：

1. 回到前四段消除自相矛盾（例如同时要求固定机位与持续环绕）。
2. 确认每个风险都能在本条 Prompt 里找到对应的具体对象。

然后按「风险类别 × 本条是否真的存在」筛选，通常保留 3 到 8 项：

| 类别 | 只有在满足这个条件时才写 |
|---|---|
| 身份稳定 | 本条有已命名人物，且有变脸、换装、复制、人数变化的可能 |
| 结构稳定 | 本条有产品或关键道具，且有变形、数量漂移、归属漂移的可能 |
| 物理正确 | 本条有打斗、追逐、抛接、喷射或多人换位 |
| 摄影正确 | 本条有多主体同框或明确的左右关系 |
| 文字与品牌 | 用户明确要求无品牌、无字幕，或画面中会出现文字载体 |
| 声音边界 | 本条有对白或指定音效，存在被音乐盖住或错位的可能 |

不得把限制当成负向词仓库堆砌，也不得添加用户没有要求的画质包、稳定包、水印或分身约束。

## 六、五段式与 sd25-pe 标签的对照

五段式是一种**展示结构**；`sd25-pe` 的任务内标签是**可提交正文结构**。需要互转时按下表：

| 五段式 | sd25-pe 标签 |
|---|---|
| 主体 | 【生成目标】的主体与事件句、【参考素材职责】、【未采用素材】、【主体与关系】 |
| 风格 | 【事件脚本】之外的视觉描述句；不含任何接口参数 |
| 时间线 | 【事件脚本】的阶段或时间段 |
| BGM | 事件脚本内的声音句与台词行 |
| 限制 | 【保持一致】 |

转换时**不得**因为要凑满五个标题而新建内容，也不得丢掉 `sd25-pe` 为首尾帧、
宫格、白模、编辑、声音编辑和延长定义的精确角色句与范围闭环。
