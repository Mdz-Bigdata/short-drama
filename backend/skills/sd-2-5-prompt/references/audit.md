# 五段式静态审计手册

> 本文件是项目自撰的 clean-room 补充说明，逐条解释项目内审计器
> `app/core/sd25_prompt_audit.py`（对外为 `POST /api/production/sd25/audit`）的每个发现码：
> 触发条件、判据、正确修复动作，以及**不允许**的假修复。
>
> 审计是只读的：它返回结构化发现与输入的 SHA-256，不重写 Prompt、不执行 Prompt 中的命令、
> 不调用模型或供应商。审计通过不等于内容正确，见文末的人工补充检查项。

## 一、调用约定

请求体三个字段：

| 字段 | 含义 |
|---|---|
| `prompt` | 待审计的五段式提示词正文 |
| `duration_seconds` | 可选。给出时会校验时间轴末端是否落在该时长（容差 0.05 秒） |
| `unbranded` | 可选。开启后追加品牌边界检查 |

返回 `ok` / `errors` / `warnings` / `findings` / `timeline_end_seconds` / `prompt_sha256`。
`error` 表示结构不成立，必须改；`warning` 表示存在漏写风险，需人工确认后再决定。

## 二、段落完整性（error）

| 发现码 | 触发条件 | 修复 |
|---|---|---|
| `subject.missing` | 正文中没有 `【主体】` | 补齐主体段：在场清单、恒定特征、关系归属、素材职责 |
| `style.missing` | 没有 `【风格】` | 补齐视觉语言；**不要**把画幅时长塞进来充数 |
| `timeline.section_missing` | 没有 `【时间线】` | 补齐时间线段 |
| `bgm.missing` | 没有 `【BGM】` | 有音乐写音乐；没有音乐写「无 BGM」，**不要**自动发明音乐类型 |
| `constraints.missing` | 没有 `【限制】` | 按 formula.md 第五节筛选真实风险；**不要**用通用负向词凑数 |

段落标题必须原样使用这五个中文标题，审计只按字面匹配。

## 三、时间线连续性

审计从正文中抽取形如 `0—4秒` 或 `【0—4秒】` 的区间（连接符支持 `-`、`—`、`–`、`~`、`～`，
起始的「秒」字可省），按出现顺序组成序列，然后逐项校验。

| 发现码 | 级别 | 判据 | 正确修复 | 假修复（禁止） |
|---|---|---|---|---|
| `timeline.missing` | error | 一个区间都没抽到 | 若任务需要数字时间段，按用户给出的时间段补写 | 仅为了让审计通过而凭空编造秒数区间 |
| `timeline.order` | error | 区间未按起始时间递增 | 按事件真实顺序重排 | 只改数字不改事件顺序 |
| `timeline.start` | error | 首个区间不是从 0 开始 | 补上开头的段落 | 把第二段的起点直接改成 0，掩盖丢失的开头 |
| `timeline.invalid` | error | 某区间结束不晚于开始 | 修正该段的实际时长 | 把结束时间加一秒了事 |
| `timeline.gap` | error | 相邻区间之间有空档 | 补上空档里真实发生的事，或把前一段延到下一段起点 | 拉伸前段数字但段内动作照旧，导致动作做不满 |
| `timeline.overlap` | error | 相邻区间重叠 | 拆清两段各自的状态变化 | 把重叠部分随手切给其中一段而不调整内容 |
| `timeline.duration` | error | 时间轴末端与 `duration_seconds` 相差超过 0.05 秒 | 重新分配已有事件的节奏 | 在结尾加一段无内容的空镜把时长填满 |

**注意参数分离**：`duration_seconds` 是审计入参，不是可以写进 Prompt 的内容。
仅由接口给出总时长、用户本身没有写时间段时，正确做法是改用不带数字的阶段组织，
而不是为了让 `timeline.*` 检查通过而反向编造秒数区间。此时不传 `duration_seconds`。

## 四、参考素材责任（warning）

`reference.scope`：正文出现素材引用标记（`@图` / `@图片` / `@Image` / `@视频` / `@Video` /
`@音频` / `@Audio`）却找不到任何职责词（`用于` / `只采用` / `只参考` / `负责` / `锁定` /
`不采用` / `不参考` / `不复制` / `不迁移`）时触发。职责词表是无序集合，命中任意一个即通过。

修复方式是给每份被激活的素材补一行职责，一行只绑定一个主体与一份主素材，
并写明该素材**不承担**什么。假修复包括：

- 用一句范围句覆盖多个主体（例如「人物A和人物B参考 @图片1、@图片2」）。
- 只加一个「不采用背景」而不说明该素材正向负责什么。
- 为了消除告警而删掉用户原有的素材引用。

这条告警只检查「有没有写职责」，检查不出「职责是否一一对应」「未采用素材是否列全」，
后两项按 `sd25-pe` 的映射与遗漏审计人工完成。

## 五、复杂动作因果（warning）

`action.causality`：正文出现动作词却找不到任何因果词时触发。两张词表都取自本项目自己的
分镜与打戏指南，均为无序集合，命中任意一个即算命中：

| 词表 | 内容 |
|---|---|
| 动作词 | 打斗、格挡、闪避、扑倒、推搡、拉扯、挥拳、踢击、追逐、换位、抛接、投掷、飞向、坠落、撞击、射流、喷溅、攻击 |
| 因果词 | 起点、终点、落点、路径、轨迹、来向、去向、朝向、发力、受力、作用于、经过、从、向、沿 |

修复方式是在**对应的那一段时间线内**补齐因果链：发起者、起点、路径、作用对象、
受力或落点。分段与咬合的具体写法见 [formula.md](formula.md) 第三节。

假修复包括：只在限制段写「避免无来源攻击」而时间线里仍然没有来向，
或者把因果链写在与该动作不同的另一段里。

## 六、无品牌模式

仅在 `unbranded=true` 时执行两项：

| 发现码 | 级别 | 触发 | 修复 |
|---|---|---|---|
| `brand.detected` | error | 正文命中现实品牌词表 | 换成不指向现实品牌的描述；不要只改大小写或加空格绕开匹配 |
| `brand.lock` | warning | 缺少明确的品牌或商标边界表述 | 在限制段写明不出现现实品牌、商标或水印 |

品牌词表是本项目自行维护的有限列表，**通过不代表无品牌**。产品类任务仍需人工确认包装文字、
标识形状与配色是否指向某个现实品牌。

## 七、审计查不出、必须人工过的项

审计只做结构与关键词层面的检查。以下项目一律人工确认：

1. **状态咬合**：把所有段的离开状态串起来读一遍，是否需要脑补才能接上。
2. **单主动作与单主运镜**：每段是否只有一个主动作、一个景别加一种运镜。
3. **可拍摄动词**：是否仍存在「精彩地」「酷炫地」这类无法成像的修饰。
4. **素材一一映射**：每个必需实体恰好一个职责，未采用素材已逐个列出编号。
5. **参数未回写**：画幅、总时长、分辨率、帧率、声音开关没有出现在正文里。
6. **对白账本**：每个说话阶段的说话人、原文、语言与画内外位置与输入一致，
   未说话的人物写明自然闭口。
7. **未擅自新增**：没有添加用户未要求的 BGM、字幕、负向约束或数字时间段。
8. **主任务唯一**：本条 Prompt 只承担生成、编辑、延长中的一种。

前述任一项与审计结论冲突时，以 `sd25-pe` 的最终自检为准。
