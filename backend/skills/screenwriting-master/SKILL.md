# 结构化编剧规约（Writer Agent）

本规约描述编剧智能体产出剧本的方式。运行时实现见 `backend/app/core/screenwriting/`，
本文件是规约正文，不被执行。

## 一、两段式生产

剧本分阶段产出；除小说体正文输出纯文本外，各阶段都是受 JSON Schema 约束的模型调用：

| 阶段 | 产出 | 一旦定稿 |
|------|------|----------|
| 分集账本 | 每集的标题、集尾钩子、故事节点、下集预告语 | 后续每集写作的依据，剧本内容须覆盖全部故事节点 |
| 分镜内容层（script_plan） | 分镜边界、时长、出场角色 / 场景 / 道具、逐字口播 utterances、原文锚 source_text、视觉改编描述 | 内容真相源，视觉层原样透传、不再改写 |
| 小说体正文（prose） | 本集给人读的剧本正文：叙述段落 + 引号对白 | 剧本正文 `assets["2"]` 的内容，不回写内容层 |
| 视觉层（prompt authoring） | 每个分镜的 image_prompt 与 video_prompt | 按 scene_id 与内容层合并 |

**为什么分两段**：非视觉字段（台词、原文、出场资产、时长）不进第二次模型调用的输出，
它们就不可能在第二次调用里漂移。合并按 scene_id 对齐，缺覆盖、悬空 id、重复 id 一律拒绝。

## 二、三种源文模式

| source_kind | 输入 | 口径 |
|-------------|------|------|
| `outline` | 只有总导演策划方案 | 按分集大纲**创作**分镜内容 |
| `novel` | 小说原文 | 把原文**改编**为分镜内容，旁白由语境判断 |
| `screenplay` | 作者已写好的成品剧本 | 从剧本中**提取**，台词与旁白逐字保留 |

`novel` / `screenplay` 的分集按逐字 `end_anchor` 锚点切分：每集内容 = 上一集结尾之后到该锚点末尾的原文。
锚点必须在原文中唯一出现且位置严格递增，否则该轮产出被拒并把原因回传给模型重试。

## 三、内容约束与修复

产出违反约束时不丢弃重抽，而是按类型处置：

| 违约 | 处置 |
|------|------|
| scene_id 集号或格式错误 | 机械改写为当前集号，记为警告 |
| 台词说话人不在出场角色里 | 补入出场角色并登记为角色资产，记为警告 |
| 时长不在视频模型支持的档位内 | 就近取合法档位，记为警告 |
| 口播念不完该分镜时长 | 提到能装下的最小档位，记为警告 |
| 口播超过单镜最长时长 | 回传模型要求拆分；重试耗尽则标 needs_replan 待人工重拆 |
| `screenplay` 模式台词与原文不符 | 回传模型要求逐字保留 |
| scene_id 重复 | 回传模型重出 |

详细规则见 `references/shot-content-rules.md` 与 `references/visual-layer-rules.md`，
节奏建议见 `references/episode-pacing-drama.md` 与 `references/episode-pacing-narration.md`
（后两者同时由提示词构建器读取，仓库里只有一份文本）。

## 四、剧本正文是小说体

剧本正文是给人读的，不是分镜表：每集一行 `第N集 标题`，其下是小说体叙事——一段一行、段间空一行，
台词放进中文引号“”，说话人的动作与神态写在引号前后。场景 / 镜头 / 画面 / 时长这类标签行、
「角色名：台词」的剧本体对白、括号舞台提示、分镜编号都不进正文；分镜边界、景别运镜与时长只存在于结构化分镜与大纲里。

| source_kind | 正文来源 |
|-------------|----------|
| `outline` | 内容层定稿后由模型写成小说体；内容层的每句口播必须**逐字**出现在正文里（允许在原有标点处被动作隔开） |
| `novel` / `screenplay` | 该集在源文里的切片，逐字呈现，不重述 |

正文草稿未通过校验（缺台词、出现标签行或剧本体对白、过短）会带着原因重试；重试耗尽则由分镜内容机械合成正文并记
`prose_fallback` 警告。只有软性问题（多出的台词、括号提示）的草稿重试一次后保留，记 `prose_unverified` 警告。
编辑分镜规划时，只有正文取材的字段（场景标题、视觉描述、口播、分镜顺序）变了才重写该集正文。

## 五、时长契约

单分镜时长必须落在**所选视频模型单次生成能力**决定的档位内（`app.core.video_references`），
因为每个分镜都要被该模型一次生成出来。单集目标时长是软目标：内容不足宁可少拆，
内容需要可以超出，只提示不阻断。

## 六、增量重写

每个分镜记住它当时消费的内容层指纹。编辑分镜规划后，只有内容真的变了的分镜重写视觉层，
其余分镜的提示词与已生成产物原样保留。
