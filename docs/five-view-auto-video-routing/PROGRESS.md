# 五视图与自动视频路由进度

## 状态：离线实现与验证完成；外部供应商实测待配置

### 2026-08-15

- 已阅读构建规范并建立研究、实施与进度文档。
- 已核对截图中的严格五视图顺序与禁止项。
- 已审计目标 Markdown、九宫格结构、视频引用规划、模型网关和前端模式选择。
- 已识别现有自动模式会被角色参考图固定抢占的问题。
- 已核对主要供应商公开能力边界；决定采用“镜头意图评分 + 运行时能力协商 + 可追溯降级”。
- 未调用任何付费供应商，也未持久化用户曾粘贴的密钥。

### 完成结果

- 指定模板已完整升级为严格五视图，并补充九宫格、四类资产、自动视频模式和交付检查表。
- 新增 `ShotMotionContract`，同一语义契约编译分镜图与运镜提示词；语义/素材分别计算指纹。
- 新增可解释的视频路由：首尾帧、多图/宫格、多模态和首帧/文本降级均经过模型能力协商。
- MiniMax H3、Seedance、Kling、Grok、HappyHorse、LTX-2.3 均有独立能力档案和别名；未配置供应商不会伪装成已提交。
- 新增 `/api/production/video/route`，前端逐镜显示实际模式、供应商族、理由和契约摘要。
- 124 个后端测试、8 个后端 subtests、8 个前端测试、Ruff、ESLint、TypeScript/Vite 构建和生产依赖审计通过。
- 工作区扫描确认未包含用户曾粘贴的 ElevenLabs 密钥。

## 外部依赖

- Kling、Grok、HappyHorse、LTX 等真实调用仍需要各自合法 API 凭据、运行时端点、对应供应商适配器和付费预算；本次完成的是统一模式契约、能力档案与自动路由，不伪装成已提交。
- Seedance 2.0/2.5 的具体可用模式以账号实际开放的端点能力为准。
- 首次真实供应商验证应使用已轮换的密钥和小额 canary，不使用聊天中出现过的密钥。
